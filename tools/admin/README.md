# NijiEhon 本地后台

在 Windows 双击 `打开后台.cmd`，或在仓库根目录运行 `node tools/admin/server.mjs`。需要 Node.js 22 或以上。后台监听 [127.0.0.1:5621](http://127.0.0.1:5621/)，并通过本机 Git 发布。用 GitHub Desktop 继续操作也可以。

## 编辑内容

- **商品**可先存草稿，填写地区、分类和简介后上架，也可随时下架。权重 5 优先于 1，首页取前三项。价格可以待公布、显示固定价格或起始价格，可选币种和计价单位。现有商品已导入，价格默认待公布。商品详情的购买按钮为禁用状态。
- **文章**可设作者、发布时间、置顶、权重和相关商品。排序依次看置顶、权重、发布时间。阅读时间可填整数分钟，留空按正文估算。发布时间输入使用本机时区，网页日期按北京时间显示。未来日期的文章会在到点后的下一次生成或部署加入网站。写正文时用空行分段，可以用 `# `、`- ` 和 `> ` 开始小标题、列表和引用。
- **首页海报**支持 JPEG、PNG、WebP 和垂直裁切位置。后台和网站都按 16:9 取景。图片文件上限为 10 MB。
- **用户与订单**保留入口，购买系统上线后再接入。

## 预览与部署

1. 点击「保存」保存到本机。编辑器的预览会展示保存后的当前记录，包括草稿。顶部「预览网站」展示当前可以发布的内容及首页海报。两处预览都使用网站原有的样式和导航。
2. 点击「生成网站」更新仓库根目录的页面、搜索索引和发布快照，然后运行静态检查。可以在 GitHub Desktop 查看改动，并通过 Commit to main → Push origin 发布。
3. 点击「部署」也能生成、提交并推送已准备好的内容。后台使用现有 Git 凭据，推送 `origin/main` 后由 Cloudflare Pages 自动构建。首次把后台及公共样式纳入版本时，先用 GitHub Desktop 审核并推送这些项目文件。之后后台只提交生成的内容，其他代码改动和远程分支分歧继续用 GitHub Desktop 处理。[Cloudflare Pages 部署记录](https://dash.cloudflare.com/1abaa82b108729621cc731ab27be8d88/pages/view/nijiehon)

本机草稿与待用图片位于被 Git 忽略的 `tools/admin/.local/`。生成后的 `published.json` 只记录当次公开的商品、文章和海报，已公开过的内容撤下后会保留通用提示页，避免旧链接继续显示原文。换电脑时如需继续编辑本机草稿或已撤下记录，请一并带上 `.local` 目录，并用相同的 Git 提交作为基线。Cloudflare Pages 当前只收录根目录网站文件和 `assets`，后台程序和本机草稿均不进入构建产物。
